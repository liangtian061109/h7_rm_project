## 速度环接入底盘解算，并把两者拆开

用户问「这个不用接速度环吗」——指的是 `Chassis_Solve` 的输出。

### 其实早就接上了
`C620_SpeedLoop()` 内部先解算写 `g_c620_target_rpm[]`，下面同一个 for 循环拿它当 PID 目标。
链路：`g_chassis_vx/vy/wz → Chassis_Solve → g_c620_target_rpm → Slope → Pid_Control → C620_SetCurrent`。

### 但结构有问题，拆成两个函数
原来解算夹在 `#if !C620_SPEED_TEST` 里塞在 `C620_SpeedLoop` 中间，
函数名叫 SpeedLoop 却干了三件事（解算/斜坡/PID），看不出"接上了"。

拆成：
- `C620_UpdateTarget()` —— 车体速度 → 四轮目标。以后接遥控/自动/小陀螺只改这里
- `C620_SpeedLoop()` —— 目标 → 斜坡 → PID → 电流。不关心目标从哪来

任务主循环里依次调用。

### 一个细节
测试模式（`C620_SPEED_TEST=1`）下 `C620_UpdateTarget` 直接 `return`，不覆盖目标。
这样调试器还能实时改 `g_c620_target_rpm[]` 做阶跃测试。若每帧写死 100 就改不动了。

FLASH 99812 B。纯重构，行为不变。

## 麦轮解算公式已验算通过（离线）
`(vx ± vy ± rot) × (1/√2)`，`rot = wz × √((轮距/2)²+(轴距/2)²)`。
几何：轮径 85mm、轴距 346mm、轮距 346mm → d = 244.7mm。
反算回 vx/vy/wz 完全一致。
**注意**：旧工程 `gk_rm_demo` 用 `(L+W)/2 = 346`，偏大 41%，自转会转太快。

## 接 Xbox 手柄（冰原狼）做遥控 —— USB Host 改造

用户：「我没 dbus 的遥控器拿的游戏手柄冰原狼」。参考仓库
qixinzhao1/STM32F4_XBOX_USB（README 明确写了针对飞智冰原狼2）。

### 前置发现
- 原 USB 配置是 **Device CDC**，但 PA11/PA12 **从来没配过 AF**，
  `CDC_Transmit` 也从没调用 → 这个虚拟串口一直是摆设，改成 Host 零损失
- `stm32h7xx_hal_hcd.c` 和 `stm32h7xx_ll_usb.c` 早就在 Drivers 里（配 USB 时带的）
- 删掉 USB_DEVICE 后 DTCM 从 32008 降到 27576（CDC 那 4KB 缓冲没了）

### 新增文件
| 文件 | 作用 |
|---|---|
| `BSP/usb/usbh_conf.h` | Host Library 配置，USBH_USE_OS=0、IN_NAK_PROCESS=0 |
| `BSP/usb/usb_host.c/h` | HCD 初始化 + USBH_LL_* 适配 + Xbox class + 轮询 |
| `modules/xbox/xbox.c/h` | 20 字节报告解析 + 摇杆归一化（纯算法，无硬件依赖） |
| `APP/task/module_tasks/rc_task/` | 每 1ms 推 Host 状态机 + 手柄→底盘速度映射 |
| `Middlewares/ST/STM32_USB_Host_Library/` | ST 原版 4 个 .c（从仓库拷） |

### 关键实现点
1. **识别靠接口类码 FF/5D/01，不是 VID/PID**。ST 的 USBH_FindInterface 用 0xFF
   当通配符，必须逐槽校验 bInterfaceClass/SubClass/Protocol/AlternateSetting/双端点
2. **NAK 不算错误**。无线接收器空闲时一直 NAK，到 interval 就重新提交 URB；
   当错误处理会不停重枚举
3. **一次只挂一个 IN URB**，状态推进全在 BgndProcess（工作线程），
   SOF 回调里什么都不做（那在 HCD 中断里）
4. **`USBH_LL_Connect/Disconnect/SetTimer/PortEnabled/PortDisabled` 是 Core 自带的**，
   不要自己实现（会 multiple definition）。只有 HCD 对接那 8 个要自己写
5. `USBH_LL_Disconnect` 内部会调 `USBH_LL_Stop`，所以本地状态要在 HCD 回调里清

### 配置改动
- `cmake/stm32cubemx/CMakeLists.txt`：PCD→HCD、USB_Device_Library→USB_Host_Library
- 根 `CMakeLists.txt`：给 `stm32cubemx` INTERFACE 补 `BSP/usb` include
  （Host Library 的编译单元在 Middlewares 下，拿不到 auto_add_sources 的路径）
- `Core/Inc/stm32h7xx_hal_conf.h`：PCD 关、HCD 开
- `Core/Src/stm32h7xx_it.c`：`HAL_PCD_IRQHandler` → `HAL_HCD_IRQHandler`
- `Core/Src/freertos.c`：删 `MX_USB_DEVICE_Init`
- `rm_project.ioc`：USB_DEVICE→USB_HOST、VirtualMode-Device_Only_FS→Host_Only_FS
  （备份在 `rm_project.ioc.bak`，若 CubeMX 打不开就恢复）

### 任务优先级
rc_task = 30，低于 c620(50) 和 bmi088(54)。因为 USB 枚举时 `USBH_Delay(200)` 会阻塞。

### 待上板验证（重要）
1. **VBUS 供电**：接收器要 5V，板子 OTG 口必须能输出。`vbus_sensing_enable=DISABLE`，
   Host 靠设备插入时 DP 上拉感知，不靠 VBUS 检测
2. 摇杆方向符号：`RC_Map_To_Chassis` 里 vy/wz 取了负号（X 右为正、wz 逆时针为正），
   实测反了就改符号
3. `g_rc_enable` 默认 0，插上手柄也不接管，要手动改 1 才生效

FLASH 103128 B（+2.2KB）。零警告。
