## 用 BMI088 数据手册核对上一轮的 SPI/BMI088 讲解

手册：`C:\Users\30710\Documents\BMI088 Datasheet.pdf`（BST-BMI088-DS000-19，Rev 1.9，62 页）

**核对通过（可以照写）**：
- 加速度计读要哑字节、陀螺仪不要（§6.1 / §6.1.2）
- 加速度计读 6 个数据要 8 字节传输（1 地址 + 1 哑 + 6 数据）；单字节读要 3 字节
- 陀螺仪单字节读写是 16-bit 协议：bit0=R/W，bit1-7=地址，bit8-15=数据
- CHIP_ID：加速度计 0x00 → 0x1E；陀螺仪 0x00 → 0x0F
- 寄存器地址全部正确（ACC 0x12/0x22/0x40/0x41/0x7C/0x7D/0x7E；GYRO 0x02/0x0F/0x10/0x14）
- 软复位都是写 0xB6；加速度计等 1 ms，陀螺仪等 30 ms（§5.3.22 / §5.5.8）
- SPI 最高 10 MHz（Table 12）；支持 mode '00' 和 '11'（§6.1）
- 温度：uint11 = MSB*8 + LSB/32，>1023 减 2048，×0.125 + 23；**1.28 s 才更新一次**
- 换算：±24g → 1365 LSB/g；±2000dps → 16.384 LSB/dps
- ACC_CONF=0xAC → bwp=Normal(0x0A) + ODR=1600Hz(0x0C)
- ACC_RANGE=0x03 → ±24g；GYRO_RANGE=0x00 → ±2000dps；GYRO_BANDWIDTH=0x81 → 2000Hz/230Hz（bit7 恒 1）

**上一轮讲错的两点（已在本轮更正）**：
1. 切 SPI 模式的哑读不是 0x7F，而是 **ACC_CHIP_ID(0x00)**。加速度计上电默认 I²C 模式，
   靠 CSB1 上升沿切到 SPI，**第一次读的返回值无效**。所以初始化必须连读两次或加重试循环。
2. 上一版把软复位写在 CHIP_ID 检查之前 —— 顺序反了，必须先哑读切模式再软复位。

**补充规格**：SPI 两次写访问之间要留空闲，normal 模式 ≥2 µs，suspend 模式 ≥1000 µs。
加速度计复位后处于 suspend，配置阶段每次写后至少等 1 ms（代码里用 HAL_Delay(2) 覆盖）。

## BSP 抽象风格定调：CS 统一低有效，不加 per-instance 极性字段

用户否决了 `cs_active_level`。理由成立：本板所有 SPI 从设备（BMI088 加速度计/陀螺仪）
都是低有效，加一个"永远等于 GPIO_PIN_RESET"的字段属于死状态，还让
`SPI_Cs_Select/Release` 从常量操作退化成需要查配置的三元表达式。

**结论（后续写 BSP 都按这个来）**：
- 片选极性写死低有效，直接 `GPIO_PIN_RESET` / `GPIO_PIN_SET`。
- 参考工程 H7_BSP 之所以有 `Activate_Level`，是因为它同时支持 F1/F4/G4/H7 多块板、
  还挂了 WS2812/OSPI 等杂项；本项目是单板单机器人，抽象预算不同。
  **移植参考工程要按自己的抽象预算裁剪，不能照抄字段。**

## SPI2 时钟：参考工程其实是 80 MHz / 10 MHz（更正）

之前按用户工程的 M=2/N=16 推算参考工程是 192 MHz，**错了**。参考工程 `Core/Src/spi.c` 的
MspInit 里 PLL3 是：

```
PLL3M=24, PLL3N=160, PLL3P=2, PLL3RGE=VCIRANGE_0, PLL3VCOSEL=VCOMEDIUM
→ 24/24=1 MHz ×160=160 MHz VCO ÷2 = 80 MHz spi_ker_ck
→ BaudRatePrescaler_8 → SCK = 10 MHz（正好卡 BMI088 上限）
```

用户工程现状：`PLL3M=2, N=16, P=1` → 12 MHz ×16=192 MHz ÷1 = **192 MHz kernel，÷8 = 24 MHz SCK**，
是参考工程的 2.4 倍。

**两种改法**：
- 抄参考：M/N/P = 24/160/2 → 80 MHz，配 prescaler 8 → 10 MHz 或 16 → 5 MHz。
  注意改 M 会连带 RGE（8-16MHz → 1-2MHz）和 VCO 区间（WIDE → MEDIUM）一起变。
- 最小改动：只把 PLL3P 由 1 改 2 → 96 MHz，配 prescaler 16 → 6 MHz（VCO 仍 192，贴着 WIDE 下限）。

**建议先用 5~6 MHz 调通**（出问题必是代码问题，不是时序），跑通后再试 10 MHz。
PLL3 只喂 SPI1/2/3，改它不影响 SYSCLK / USB(HSI48) / FreeRTOS tick，是安全的。

## H7_BSP 的 SPI 到底是 DMA 还是阻塞

`User_File/Middleware/BSP/SPI/bsp_spi.cpp` 里是**按外设分支**的：
- `hspi->Instance == SPI6` → 阻塞 `HAL_SPI_Transmit` / `HAL_SPI_TransmitReceive`（SPI6 是 WS2812，
  TXONLY、无 CS、无 RX，走阻塞更省事）
- 其余（含 SPI2/BMI088）→ `HAL_SPI_Transmit_DMA` / `HAL_SPI_TransmitReceive_DMA`

**异步的三个连带后果（移植时最容易漏）**：
1. 函数返回时数据还没到，**CS 也还是低的**——`SPI_Deactivate_Chip_Select()` 是在
   `HAL_SPI_TxRxCpltCallback` / `HAL_SPI_ErrorCallback` 里才调用的。
2. 所以 BMI088 驱动里的 `Read_Single_Register()` 是"发命令就返回"，数据靠
   `SPI_RxCpltCallback()` 填进 `Register`。**`Init()` 里那些 `Delay_Millisecond(100)`
   不是等器件，是在等 DMA 回调。** 这是个设计坏味道，别抄。
3. Tx/Rx 必须先 `memcpy` 到 `SPI2_Manage_Object` 的常驻缓冲（放在 `.dma_buffer` → RAM_D1），
   因为栈上的数组在 DTCM，DMA1 访问不到，而且 DMA 跑完前调用方缓冲可能已经出作用域。

## 用户决定要上 DMA（方案：DMA + 信号量，保持同步接口）

用户明确表示"我的也需要 DMA"。给出的方案**不照抄参考工程的回调金字塔**：
`HAL_SPI_TransmitReceive_DMA` 启动后，用 `osSemaphoreAcquire` 等完成信号量，
回调里 `osSemaphoreRelease` + 拉高 CS。这样：
- CPU 不陪等，其他 FreeRTOS 任务可运行
- 上层 BMI088 驱动接口不变（仍是"函数返回时数据已在"），不需要参考工程那种
  `Delay_Millisecond(100)` 硬等回调
- 不需要 callback 金字塔和 readback 哨兵值

**配套必改项**：
1. 链接脚本加 `.dma_buffer (NOLOAD) >RAM_D1`，`spi_instances[]` 整块放进去
   （结构体成员不能单独指定 section，只能整个数组加属性）。
2. 超时必须调 `HAL_SPI_Abort()`，否则 HAL 状态卡在 BUSY_TX_RX，之后全是 HAL_BUSY。
3. DMA1_Stream0/1 与 SPI2 的 NVIC 优先级必须 ≥ 5（= configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY），
   否则 ISR 里 `osSemaphoreRelease` 会触发断言。本工程 ioc 里都是 5，已满足。
4. 同一 handle 上 accel/gyro 两个实例共用一个 DMA 完成回调，靠
   "找 busy==1 的那个实例" 定位归属，并用总线互斥量保证同时只有一个事务在飞。

**API 简化**：删掉等长的 `SPI_TransmitReceive()`（语义和 Ex 混淆），保留
`SPI_Transmit` / `SPI_Receive` / `SPI_TransmitReceiveEx(tx,tx_len,rx,rx_len)`。
线长 wire_len = tx_len + rx_len，有效数据从 rx_buf[tx_len] 开始。

## 用户要求：工创项目要和 H7_BSP 架构 1:1 对齐

理由不是技术选型，是**比赛/团队要求框架一致**。所以后续按参考工程的写法给：

**核心是"一外设一管理对象"模型**（不是一从设备一实例）：
- `Struct_SPI_Manage_Object` × 6（SPI1..SPI6），全局唯一，含 handler / Callback_Function /
  Transaction_Active / CS 信息 / 512B Tx+Rx 常驻缓冲 / 长度 / 时间戳 / 错误计数
- `SPI_Init(hspi, callback)` 只绑 handler 和回调
- `SPI_Transmit_Data()` / `SPI_Transmit_Receive_Data()`：校验 → 抢事务 → memcpy 到常驻缓冲 →
  拉 CS + 启动 DMA → 返回
- 完成中断：拉 CS → 时间戳 → 调 Callback_Function → 释放事务

**设备层精髓（SCUT-Robotlab 风格）**：
用 `#pragma pack(1)` 的结构体**逐字节镜像寄存器地址空间**，靠 `offsetof()` 得到寄存器地址，
回调里一句 `memcpy((uint8_t*)&Register + addr, &Rx_Buffer[1+dummy], len)` 批量灌入。
建议额外加 `_Static_assert(offsetof(...) == 0xXX)` 做编译期校验（参考工程没做，容易错位）。

命名保持参考工程风格：`SPI_Transmit_Receive_Data` / `Tx_Buffer` / `Callback_Function` /
`Transaction_Active` / `SPI_BUFFER_SIZE` / `.dma_buffer`。C 版把 class 换成 struct + 函数指针。
`Activate_Level` 用户已否决，保持低有效。
