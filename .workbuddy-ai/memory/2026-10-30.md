## SPI2 改为 DMA 传输

**背景**：CubeMX 侧其实已经配好了 SPI2 的 DMA（RX=DMA1_Stream0 / TX=DMA1_Stream1，
DMA_NORMAL、BYTE、优先级 5，NVIC 和 IRQHandler 全部已生成），缺的只是 BSP 层还在用阻塞 API。

**改动文件**：
- `BSP/bsp_spi.h` / `BSP/bsp_spi.c`：阻塞 `HAL_SPI_TransmitReceive` → `HAL_SPI_TransmitReceive_DMA`
  + 二值信号量 + `HAL_SPI_TxRxCpltCallback` / `HAL_SPI_ErrorCallback` 重写。
  新增 `SPI_ReadRegs()`（内部中转缓冲，调用者不必管内存位置）、`SPI_IsBusy()`、`SPI_DMA_BUF` 宏。
  总线级互斥：同一 handle 下多个 CS 实例（BMI088 accel/gyro 共用 SPI2）串行访问。
- `STM32H723XG_FLASH.ld`：新增 `.dma_buffer (NOLOAD) >RAM_D1` 段。
- `CMakeLists.txt`：把 `BSP/bsp_spi.c` 和 `BSP` include 路径接入构建（之前 BSP 目录完全没参与编译）。

**关键坑（重要，以后别踩）**：
1. H7 的 **DMA1/DMA2 无法访问 DTCMRAM(0x20000000)**。本工程 `.data/.bss` 全在 DTCM，
   所以 DMA 缓冲必须放 RAM_D1(0x24000000)。栈上的局部数组也在 DTCM，同样不能用。
2. SPI2 是 2LINES 全双工，只发送也必须走 `TransmitReceive_DMA` + 哑 RX 缓冲，
   否则 RX FIFO 溢出会清 SPE。
3. 超时必须调 `HAL_SPI_Abort()`，否则 DMA/SPI 卡住，后续全是 HAL_BUSY。
4. SPI2/DMA1 IRQ 优先级都是 5，等于 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`，
   刚好可以调用 `xSemaphoreGiveFromISR`。

**顺带修的旧 bug**：`SPI_Transmit()` 里 `tx/rx` 未定义；`SPI_MAX_INSTANCES` 与头文件
`SPI_MAX_INSTANCE` 名字不一致；头文件缺 `#endif` 和函数声明。

**工具链**：`C:\Users\30710\AppData\Local\stm32cube\bundles\gnu-tools-for-stm32\14.3.1+st.2\bin`
（不在 PATH，`cmake --preset Debug` 会因找不到 arm-none-eabi-g++ 报错，
直接用 `cmake --build build/Debug` 增量构建即可）。

## 补充：对照 H7_BSP 仓库做 SPI 移植教学（只讲解，未改文件）

参考工程：`D:\stm32halproject\gk_rm_demo\rm_project`（C，BSP/Modules/APP 三层，实例池 + Register 模式）
移植来源：`https://github.com/MermaidFAR/H7_BSP`（C++，`User_File/Middleware/BSP/SPI` + `User_File/Device/Onboard/BMI088`）

**本轮新查到的硬事实**：
1. 当前 SPI2 内核时钟 = PLL3(24/2*16/1) = **192 MHz**，超出 SPI1/2/3 的 spi_ker_ck 上限（100 MHz）；
   预分频 8 → SCK 24 MHz，超出 BMI088 的 10 MHz 上限。建议 PLL3P=2（96 MHz）+ 预分频 16 → 6 MHz。
2. 参考工程 SPI2 用 **mode 3**（CPOL=High / CPHA=2Edge），本工程是 mode 0。BMI088 两种都支持，
   但建议对齐参考工程。
3. BMI088 关键差异：**加速度计读寄存器要多发 1 个哑字节**（tx=2, rx=len），陀螺仪不用（tx=1, rx=len）。
   所以 BSP 必须提供"非对称收发"原语，等长的 `SPI_TransmitReceive` 不够用。
4. `SPI_CheckDevice()` 属于层次错误（命令字节+哑字节是器件知识），应下沉到 BMI088 模块。
5. 本工程 `.data/.bss` 都在 DTCMRAM，DMA1 访问不到；但当前 **D-Cache 未开启**（main.c 无 SCB_EnableDCache），
   DMA 一致性暂时不用处理。
6. CMakeLists.txt 的 `target_sources` 是空的，`BSP/` 目录完全没参与编译 —— 最隐蔽的问题。
7. 用户工程里 `modules/`（小写）与旧工程 `Modules/`（大写）不一致，写 CMake glob 时要注意。
