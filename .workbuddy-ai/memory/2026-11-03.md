## 全局去掉数字字面量的 U/L 后缀

用户：「代码整理一下数字后面都不用带u」。

范围：APP / BSP / modules（Core、Drivers、Middlewares 是生成代码，不动）。
结果：173 处，其中 `U` 171 处、`UL` 2 处，替换后残留 0，编译 0 警告。

### 三个需要确认的点（已验算安全）
- `(1UL << 0)` → `(1 << 0)`：移位量 0/1，无溢出风险
- `0xFFFFFFFFU` → `0xFFFFFFFF`：十六进制常量放不进 int 时自动选 unsigned int，
  类型不变（bsp_can.c 的过滤器索引哨兵值）
- `8192U` → `8192`：在 int 范围内

### 什么情况下 U 不能去（以后写代码注意）
1. `1U << 31` 这类移位：`1 << 31` 是有符号溢出，UB。必须写 `1U << 31`
   或 `(uint32_t)1 << 31`
2. **大于 INT_MAX 的十进制常量**：C 标准里十进制无后缀常量的类型序列是
   int → long → long long，**跳过 unsigned**。所以 `4294967295` 去掉 U 后
   变成 long（64 位），而 `0xFFFFFFFF` 去掉 U 仍是 unsigned int。
   同一个值，不同写法，类型不同 —— 这是 C 的一个坑。

FLASH 97712 B 完全不变，说明类型推导结果一致，零行为变化。

## 任务创建改为表驱动，集中到 app_task.c

用户问「任务创建要写在 apptask？还是怎么说你先说想法」，讨论后确定集中方案。

### 最终结构
`app_task.c` 里一张 `task_table[]`，每行一个任务的全部创建参数：
```c
typedef struct {
  TaskFunction_t entry;
  const char *name;
  uint16_t stack_words;
  UBaseType_t priority;
  TaskHandle_t *handle;
} Task_Config_s;

static const Task_Config_s task_table[] = {
    {BMI088_Task, "bmi088", 512, 54, &g_bmi088_task_handle},
#if APP_CAN_ENABLE
    {C620_Task, "c620", 384, 50, &g_c620_task_handle},
#endif
};
```
`App_Init_Tasks()` 变成 for 循环遍历表创建。

### 删除的东西
- `bmi088_task.c` / `c620_task.c` 里的 `XXX_TASK_STACK_WORDS`、`XXX_TASK_PRIORITY` 宏
- `BMI088_Task_Init()` / `C620_Task_Init()` 两个函数
- 两个头文件里的对应声明

### 保留的东西
- `C620_TASK_PERIOD_MS`（任务内部节奏，创建时用不到）
- `BMI088_WAIT_TIMEOUT_MS`（同上）
- 用户自己调过的测试参数（1.0f / 1000 / 10000）原样保留

### 迁移
`g_reset_flags = RCC->RSR` 抓复位原因的代码从 `BMI088_Task_Init()` 挪到
`App_Init_Devices()`（重复调用检查之后）。app_init.c 因此需要 include app_debug.h。

### 修正之前的判断
我一开始建议「栈大小留在模块 .h，表里引用宏」，理由是和实现内聚。
后来改主意：栈够不够应该靠 `uxTaskGetStackHighWaterMark()` 实测，
而不是靠"数字放得近"。既然有硬指标，集中反而更好——一张表看全所有任务资源。

FLASH 97656 B（-56 B，删了两个 Init 函数）。
