## 讲解 modules/attitude（VQF 姿态解算）

- 用户要求「读取 attitude 代码并教怎么编写」，属于学习/讲解，未改动任何代码。
- 已确认工程结构：`modules/attitude/attitude.c/.h` 是 VQF 风格 6D 融合，
  调用点在 `APP/app_task/app_task.c` 的 `BMI088_Task()`，1.6 kHz，dt 用 DWT 测。
- 讲清的要点：
  1. 三段式：q_gyro 陀螺指数映射积分 → q_accel 加计残余倾角修正 → q = q_accel·q_gyro。
  2. `residual = R(q_accel) * a_earth_lpf` 这一句必须保留，否则 q_accel 无反馈会发散。
  3. 零偏 3x3 EKF：静止用 ZARU（tau 1.0 s），运动用倾角观测，竖直轴不观测。
  4. 分阶段实现路径 S0→S4，每阶段有独立验收标准。
- 工程约定：四元数 q=[w,x,y,z]，表示机体→地理系；控制用四元数不用欧拉角。

## 重要发现：运动零偏估计实际失效

- `Att_Update_Bias` 里 `z = residual / tau_accel`，但 residual 每帧被 q_accel 完全消掉，
  它是**单帧增量**不是稳态误差，正确量纲应是 `residual / dt`，差 1/4800。
- 实测（att_sim.py 场景 C/D）：`motion_bias_enable` 开/关，20 s 后零偏估计只差
  0.0004 °/s，姿态差 0.011°，等于摆设。真正压零偏的只有 ZARU。
- 直接改成 `/dt` 也不行：噪声放大 1600 倍，实测跑出 -1.82°/s 且符号反。
  正确修法是不要每帧完全消掉 residual，改成按 dt/tau 增益部分修正。
- 其他实测结论：急停后静止检测有约 2.7 s 死区（90°/s → 1°/s 需 4.5 个时间常数）；
  yaw 轴零偏在运动中完全不可观测，只在静止 ZARU 生效。

### 技术决定
- 函数前缀用 `AttSimple_*` 而不是 `Attitude_*`，避免和 attitude.c 撞符号。
- 教学版砍掉运动零偏 EKF（实测无效），只保留 ZARU，功能无损失。
- 低通必须用**两级一阶串联**：实测单级在这个闭环里会振荡发散（场景 C 振幅
  1.4°→1.8°→2.9° 递增），两级才稳。这一条踩过坑，别再改成单级。

### 验证结果（simple_sim.py，与 attitude.c 数值一致）
- 场景 A 收敛：0.5s→0, 1s→1.287, 2s→7.799, 3.5s→17.882, 6.5s→27.344, 11.5s→29.844
- 场景 B 零偏：bias_z 从 0 收敛到 0.300，yaw 停在 0.750°
- 场景 D 转 90°/s 两秒：yaw = 179.944°

### 踩过的坑（写测试数据时）
- 机体系加速度读数 = R⁻¹·(0,0,g)，生成测试数据要用 `q_conj` 反向旋转。
  用正向旋转会让 roll 收敛到 −30° 而不是 +30°。
- 静止检测只看"抖动"会把匀速转动判成静止（匀速转动 dev=0），
  必须再加低通角速度模长门限（1°/s）。
